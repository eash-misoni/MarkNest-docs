困ったとき：症状から原因を切り分ける

本文の用語リンクから意味・画面での場所を確認できます。

知らない言葉は、本文中の点線付きリンクをクリックすると解説ページへ移動できます。ブラウザの「戻る」で読んでいた位置へ戻れます。
状況 最初の確認
Chrome拡張を読み込めない extension/manifest.jsonが指定フォルダの直下にあるか。chrome://extensions/のエラーは何か
Popupの変更が反映されない 拡張を更新し、Popupを開き直したか。Consoleを正しい実行場所で開いているか
npmが見つからない Node.js 22と環境変数PATH。端末を開き直す
npm ciに失敗 ネット接続、proxy、npm registry、lockfileを確認。lockfileを無断書き換えしない
npm run checkが失敗 最初に失敗したジョブ・ファイル・行番号から調べる。TypeScript/JSDocと実行時エラーを区別
PRでコンフリクト 最新mainとの差分を確認。ほかの担当のコードを捨てずに相談
Issueの仕様が古い r3の確定仕様を根拠として差をIssueへ報告。推測でAPIやDB契約を作らない
本番にしかない不具合 ダミーで再現できる最小条件を作る。個人のブックマーク・トークンを貼り付けない
GitHub Projectsの値が不明 最終取得時刻を確認。APIエラーを「未設定」と混同しない
AWS権限で失敗 使用したサービス・操作・IAM権限・エラー名を記録。勝手に広い権限を追加しない

Issueに残す報告例

問題：どの操作で何が起きたか
期待：本来どうなるはずか
再現手順：最小の手順を番号で
実際：エラー文・テスト結果（秘密値は除く）
確認済み：試した方法と結果
影響：自分の作業だけか、他Issueも止まるか
必要な判断：仕様の確認が必要か、モックで続行できるか

障害や未確定事項があるときは、AIが根拠なく「対応済み」と報告しないことも大切です。
