まず取り組むこと：最初の15分

本文の用語リンクから意味・画面での場所を確認できます。

知らない言葉は、本文中の点線付きリンクをクリックすると解説ページへ移動できます。ブラウザの「戻る」で読んでいた位置へ戻れます。

自分の作業を正しいIssueに結び付けることから始めます。用語が分からなければ、その場のリンクから個別ページを確認できます。ここでは担当登録などの変更操作も登場します。

  1. リポジトリを開き、READMEとAGENTS.mdに目を通す。
  2. Projects #3で、Status = Ready・Assignee未設定のIssueを探す。PriorityがHighでもBacklogなら、まだReadyとは限りません。
  3. 興味のあるIssueを開き、目的・対象外・完成条件・依存先・試験方法が理解できるか確認する。
  4. 着手するなら、ほかの人が選んでいないか再確認し、自分をAssigneeに登録してIn Progressへ変更する。
  5. 作業用ブランチを作り、小さく実装・検査し、Pull Requestを出す。mainへ直接書き込まない。

Issueを取る前のチェック

  • 作業内容を自分の言葉で説明できる。
  • 既存のどの型・関数・画面に関係するか分かる。
  • 先に終わっている必要があるIssueを確認した。
  • 変更してはいけないもの（スコープ外）が分かる。
  • 完成したと判定する具体的な方法がある。

条件が足りないIssueは、勝手に仕様を補って着手しないでください。Issueへ質問するか、判断待ちを報告します。難しそうな作業は、独立して確認できる一部分へ分割する提案もできます。

最初の実装に不安がある場合

まずはChrome拡張を起動するだけでも十分です。このWikiのローカル環境を見てMarkNest本体の extension/ を読み込み、Consoleとnpm run checkを確認してください。以前制作した独立教材 Bookmark Explorer の explorer/ と、本体の extension/ を取り違えないようにします。
