ローカル環境：Chrome拡張を起動する

本文の用語リンクから意味・画面での場所を確認できます。

知らない言葉は、本文中の点線付きリンクをクリックすると解説ページへ移動できます。ブラウザの「戻る」で読んでいた位置へ戻れます。

このページのゴールは、自分のPCにMarkNestを準備し、Chromeで拡張機能を開き、テストを実行できるようにすることです。最初の環境準備は基本的に一度で構いません。

ここでは本番のMarkNest本体を準備します。練習リポジトリの演習中は、練習用READMEに従ってください。

1. 必要なソフトを用意する

ソフト 何に使う？
PC版Google Chrome 作成したChrome拡張機能を動かす。開発用プロフィールを推奨
Git GitHubからコードを取得し、変更履歴を管理する
Node.js 22系・npm JavaScriptのテストや型チェックを実行する。npmはNode.jsと一緒に導入される
VS Codeなどのエディタ ファイルを開いてコードを書く

すでに導入済みなら再インストールは不要です。GitHubにログインし、MarkNest本体リポジトリを開けることも確認してください。404が出る場合は招待・アクセス権を確認します。

2. ターミナルを開いて準備を確認する

ターミナルとは、文字でコマンドを入力してPCを操作する画面です。WindowsならPowerShell、VS Codeならメニューの「ターミナル」→「新しいターミナル」を使えます。コマンドは1行ずつ入力し、Enterを押します。

git --version
node --version
npm --version

それぞれバージョン番号が表示されれば利用できます。Node.jsはv22で始まるバージョンを使います。コマンドが見つからない場合はインストール状況を確認し、ターミナルやVS Codeを開き直してください。

3. GitHubからコードを取得する

初回は、作業用フォルダを置きたい場所（例：ドキュメント）でターミナルを開き、以下を実行します。

git clone https://github.com/eash-misoni/MarkNest.git
cd MarkNest

cloneはGitHubにあるリポジトリを、自分のPCへ変更履歴ごとコピーする操作です。MarkNestというフォルダが作成されます。cdはターミナルの作業場所をそのフォルダへ移動します。

すでにcloneした人はもう一度cloneせず、VS Codeの「ファイル」→「フォルダーを開く」で既存のMarkNestフォルダを選んでください。その中のターミナルを使います。最新のmainを取得する操作はIssueとPRで説明します。

GitHubの認証を求められたら、アクセス権を持つ自分のアカウントで認証します。パスワードやトークンを他のメンバー・チャットへ渡さないでください。

4. 検査に必要なツールを準備する

ここからは、MarkNestフォルダの一番上（package.jsonがある場所）でコマンドを入力します。VS CodeでMarkNestを開くと、その場所のターミナルを利用できます。

npm ci
npm run check

npm ciはpackage-lock.jsonに記載されたバージョンの検査用ツールを取得します。初回や依存関係が更新されたときに実行します。アプリを起動するコマンドではありません。

npm run checkは構文・JSDoc型・単体テストをまとめて実行します。エラーがなく最後まで終了し、テスト失敗が0件であることを確認してください。失敗した場合は最初のエラー内容を読み、原因が分からなければ相談します。

5. Chromeに拡張機能を読み込ませる

Chromeのアドレスバーに次を入力して拡張機能管理画面を開きます。これはターミナル用のコマンドではありません。

chrome://extensions/
  1. 画面右上の「デベロッパー モード」をONにする。
  2. 「パッケージ化されていない拡張機能を読み込む」を押す。
  3. PCに保存したMarkNestの中にある extensionフォルダ を選択する。
  4. 拡張機能一覧にMarkNestのカードが追加されたことを確認する。

フォルダ構成は次のとおりです。選ぶのはMarkNest全体でもmanifest.json単体でもなく、manifest.jsonが直接入っているextensionフォルダです。

MarkNest/
  package.json
  extension/       ← このフォルダを選ぶ
    manifest.json
    popup.html
    popup.js
    popup.css

以前の独立教材Bookmark Explorerのexplorerフォルダとは別です。練習用のHTMLページを開くだけの場合も、この拡張機能の読み込みは不要です。

6. 起動できたか確認する

Chrome右上の拡張機能アイコン（パズルの形）をクリックし、MarkNestを選びます。必要ならピン留めしてください。小さな画面が開きます。この画面をPopupと呼びます。

現時点の最小起動画面では「JavaScriptの動作を確認」ボタンを押すと「JavaScriptの動作を確認できました。」と表示されます。画面が開き、ボタンが動くことが今回の起動確認です。

Popup内を右クリックして「検証」を選び、開発者ツールのConsoleタブを確認します。ここにはプログラムのログやエラーが表示されます。赤いエラーがある場合は内容を確認しましょう。

最小Popupの起動確認にはAWS接続やCognitoトークンは不要です。 分類・ブックマーク操作・同期などの完成を確認する手順ではありません。実データを使う検証は、テスト専用Chromeプロフィールとダミーデータを用意してから行います。

7. コードを変更した後はどうする？

毎回cloneや拡張機能の新規登録をする必要はありません。作業用ブランチでファイルを編集して保存し、次の順番で確認します。

  1. Chromeで再び拡張機能管理画面を開く。
  2. MarkNestカードの「更新」を押す（拡張機能を再読み込みする操作）。
  3. Popupを開き直して、変更した箇所を試す。
  4. Consoleのエラーを確認し、ターミナルでnpm run checkを実行する。

検査コマンドの意味は次の表を参照してください。迷ったらnpm run checkでまとめて確認できます。

コマンド 主な用途
npm ci 指定されたバージョンの依存ツールを導入
npm run check:syntax JavaScriptの構文に誤りがないか確認
npm run check:types JSDocの型定義とコードが矛盾しないか型チェック（checkJs）
npm test Nodeの自動テストを実行し、期待した動作か確認
npm run check 上記の構文・型・自動テストを一括実行

自動テストが成功してもChromeの画面操作まで確認したことにはなりません。Issueの完成条件に合わせて、実際に試した操作と結果を記録してください。

困ったときの確認先

症状 最初に確認すること
cloneで404や403 GitHubのアカウント・招待承諾・アクセス権
npmが見つからない Node.jsの導入状況・ターミナルの再起動
npm ciが失敗する 作業場所、ネット接続、proxyやnpm registry。lockfileを勝手に変更しない
拡張機能を読み込めない extensionフォルダとmanifest.jsonの場所、Chromeのエラー表示
修正したのに画面が変わらない ファイルを保存したか、拡張機能を更新したか、Popupを開き直したか

さらに困ったら困ったときを確認してください。実装が進んだ場合は、本体READMEの最新の開発環境構築手順を優先します。
